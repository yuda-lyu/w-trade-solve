calcFitness(settings, summary) → {Number}

Description:

  • 計算策略適應值fitness

    供最佳化求解使用之目標函數值，數值越小代表策略越佳 由勝率與最終等效年化盈虧兩者組成: 勝率rWin限縮至[0,1]，等效年化盈虧rEquivalentCumuProfitOrLossFinalNormYear限縮至[0,0.5]再正規化至[0,1]，兩者皆轉為越小越好後，以權重2與1加權求和，故無懲罰時fitness落於[0,3] 交易次數為0時加上懲罰值1000000，最終累計盈虧金額(summary.uEquityFinal-settings.uIni)小於等於0時再加上懲罰值1000000，故兩者皆觸發時可達2000000以上

    Unit Test: Github

Source:
  • calcFitness.mjs, line 42
Example
let settings = { uIni: 1000 }

//勝率60%, 等效年化盈虧25%(正規化後0.5), fitness = 2*(1-0.6) + 1*(1-0.5) = 1.3
let summary = {
    numTrade: 30,
    uEquityFinal: 1200,
    rWin: '60%',
    rEquivalentCumuProfitOrLossFinalNormYear: '25%',
}
console.log(calcFitness(settings, summary))
// => 1.3

//無交易且無獲利時, 兩懲罰值皆觸發
let summaryNone = {
    numTrade: 0,
    uEquityFinal: 1000,
    rWin: '',
    rEquivalentCumuProfitOrLossFinalNormYear: '',
}
console.log(calcFitness(settings, summaryNone))
// => 2000003

calcLevelNumTrade(numTrade, optopt) → {Number}

Description:

  • 計算交易次數所屬級距代碼levelNumTrade

    交易次數過少之策略統計意義不足，過多則屬高頻，故以級距分群，使不同交易次數規模之策略各自保留最佳者 未給opt.levelNumTradeBounds時採預設級距(與K線週期無關，依4hr策略庫之交易次數規模所訂)，對應為: <=0為0，1-5為1，6-9為2，10-24為11，25-49為12，50-74為13，75-99為14，100-249為101，250-499為102，500-749為103，750-999為104，1000-1999為1001，2000-2999為1002，3000-3999為1003，4000-4999為1004，>=5000為100 給opt.levelNumTradeBounds(各級距之下界，嚴格遞增之正整數陣列，例如[1,3,6,10,20,40])時，級距代碼為不大於交易次數之最大下界，交易次數小於首個下界(含<=0)者為0，大於等於末個下界者為末個下界(末級距不設上限)；例如下界[1,3,6]時0為0，1-2為1，3-5為3，>=6為6 第2參數為設定物件(與genStrategyFileName之opt同形)，非物件者(例如作為陣列map之回呼時所收之索引)取不到opt.levelNumTradeBounds即視為未給，故[3,30].map(calcLevelNumTrade)照舊可用 numTrade非數值時throw；opt.levelNumTradeBounds給予而無效時throw(訊息為invalid opt.levelNumTradeBounds: must be a non-empty array of at most 101 strictly increasing positive integers，不含輸入值)

(async) estimKeys(ott, name, symbol, interval, fdOhlc, fdParam, timeStart, timeEnd, mode, keys, fdData, optopt) → {Promise}

Description:

  • 針對指定keys率定各key之門檻與止盈止損，求解最佳策略

    設計變數為[止損比例, 止盈比例, ...各key之門檻]，止損與止盈由opt.thsSl與opt.thsTp給予之百分比清單離散取值 各key門檻取值範圍為[-thLim,thLim]切為thLim20段，並各自平移+vdir與-vdir(vdir=thLim5)為兩組，使解值恆大於0代表'>'條件、恆小於0代表'<'條件，還原時再扣除平移值，故單一設計變數即同時涵蓋大於與小於兩種條件 未給opt.thsCond時thLim為2(格點為-2至2、步長0.1共41點，與K線週期及因子尺度無關)，還原之門檻取至小數3位；給opt.thsCond(門檻格點陣列)時改以其為各key共用之格點('>'與'<'兩組相同)，平移量vdir為max(格點絕對值之最大者,2)5(格點落於[-2,2]者同為10)，每個key之設計變數可用值為格點數之2倍，還原時直接查回格點原值(不經浮點運算，入庫之門檻必為所給格點之一) 以w-optimization之最佳化函數求解，由opt.methodOml指定演算法，各次計算皆以w-trade-backtest之runStrategy回測並經calcFitness計算適應值；亦可由opt.funRunStrategyCustom注入自訂評估核心加速求解(如以w-trade-backtest之buildStrategyFastSession預算first-touch表與因子對位序列)，注入僅回傳精簡欄位之核心時可配合opt.useRunStrategyBeforeSave於存檔前重跑完整回測，使落地summary維持完整欄位口徑；存檔前重跑後檔內numTrade、levelNumTrade、tkid、fitness與檔名皆由重跑之summary重新衍生，確保檔名與檔案內容同源一致；重算檔名與原檔名不同(評估核心與重跑結果跨級距)時，對新檔名重做存在檢查、身分驗證與優劣比較，新檔名已有更佳者則放棄本次寫入 各次計算結果若同時滿足交易次數、勝率與最終等效年化盈虧三門檻，則以genStrategyFileName產生檔名存入fdData；檔名為tkid(tid+交易次數級距)之純函數，故直接組出檔名查詢既有策略(O(1)，不列舉全庫)，同tkid已有策略時僅於最終等效年化盈虧更佳時原地覆寫，故同tkid恆僅一檔；覆寫前驗證舊檔內tkid、name、interval與keys(舊檔有keys者)與本次一致，不一致代表雜湊碰撞(tid為keys縮寫而得，縮寫後相同而keys不同者其tkid與檔名皆同)，直接throw以避免無聲覆寫 交易次數級距未給opt.levelNumTradeBounds時採calcLevelNumTrade之預設級距(與K線週期無關)，tkid為${tid}:${levelNumTrade}；給opt.levelNumTradeBounds(各級距之下界)時級距代碼為不大於交易次數之最大下界，tkid為${tid}:${levelNumTrade}@${下界以逗號串接}，檔名之雜湊隨之不同，故同一資料夾混用不同級距設定時各自去重、互不覆寫(覆寫前之tkid驗證亦含級距設定) 策略檔內容除策略本體(tid、sid、name、symbol、interval、keyOhlc、mode、conds、settings)與summary、fitness外，另落地tkid、numTrade、levelNumTrade、keys與solve區塊(timeStart、timeEnd、methodOml、thNumTrade、thRWin、thREquivalentCumuProfitOrLossFinalNormYear、thsTp、thsSl、timeSolved；給opt.thsCond或opt.levelNumTradeBounds時另於thsSl之後記轉為數值之thsCond與levelNumTradeBounds，未給者不記)，使識別與求解條件欄位自足，不依賴檔名 策略之settings為{uIni,uTrade,rTakeProfit,rStopLoss,rFee}，uIni取opt.uIni(未給為1000)、uTrade恆為1、rFee恆為0.0005；給opt.unit時另含unit(補齊buffer與units，交易規則之其他欄位如查得時刻與來源原樣保留)，回測依基礎單位定每單名義(不讀uTrade)，交易規則與緩衝隨策略檔落地；給opt.intervalSec或opt.timeBasis時再於其後附加有給之鍵(intervalSec、timeBasis，轉換後之值)，回測與重放依之；未給opt.uIni、opt.unit、opt.intervalSec與opt.timeBasis時settings與既有逐位相同 單一策略不設持倉門檻：最大持倉名義(summary.uTradeAllMax，給opt.unit時為實際名義)是否超過uIni不檢、不剔除，只隨summary落地；入庫條件與適應值不變

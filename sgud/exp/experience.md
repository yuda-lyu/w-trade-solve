# 累積經驗

本檔為執行工作時特有之累積經驗,留給後續之嘗試、執行與判斷,由agent自行編列、擴充與維護.過長時抽出舊者為`experience_<年月日>.md`,並於本檔註明何時抽出.

## 研究用本金與基礎單位(`opt.uIni`、`opt.unit`)之實作經驗

- **數值類之判定與轉換用 `isenum` + `cdbl`,不用 `isnum`**:`isnum` 定義較寬,收 `'0x10'`、`'Infinity'`、`0`(正數判定需另加);正有限數之判定用 `isenum(v, { gt: 0 })`,通過後以 `cdbl` 轉為數值使用.`cdbl` 對非數字回 0,故須先判定、不可單獨使用.
- **檢測之值即使用之值**:輸入物件若含取值器(getter),每次讀取可能不同.先 `cloneDeep` 取一次各欄之值,其後檢測(`buildBaseUnitNotional`)與轉換皆用該副本;先檢測原物件、後複製會使落地值不是通過檢測者(測試 K4 取值器案可鑑別).
- **轉換不偏離回測套件之解析**:本套件之轉型(`cdbl`、`cint`)與回測套件 `buildBaseUnitNotional` 內之轉型為同一函數;以「轉換前後 `buildBaseUnitNotional(...).key` 相同」作為測試判準,日後回測套件改動轉型時此測試會轉紅.`buildBaseUnitNotional` 只回 `{ key, getNotional }`,不回轉換後之物件,故本套件須自行轉換.
- **V20 與動態載入之錯誤訊息**:`import()` 失敗之原生錯誤訊息含檔案路徑,不可直接帶入;只帶 `err.code`(限大寫英數底線).
- **新舊口徑之比對用 `buildBaseUnitNotional(...).key`**:同 key 即同口徑,自然涵蓋數字字串與數字之同值、緩衝與單位數取預設;查得時刻與來源等記錄欄不在 key 內,故不計.既有檔之 `unit` 無法解析(內容無效)者視為不同口徑.
- **日誌之 `console.log` 攔截測試**:各案內暫換 `console.log`,`finally` 還原;mocha 之輸出只在案與案之間,不會被攔到.
- **替身核心使同一策略資料夾恆為單一檔**:摘要之 `numTrade` 固定 ⇒ tkid 固定 ⇒ 檔名固定,可精準控制「既有較佳／較差」之等效年化,用於覆寫判定之測試(口徑混存)與鑑別前提(既有高於本次,無新規則時不覆寫).

## 條件門檻之格點與交易次數之級距之實作經驗

- **預設格點帶累加誤差**:`wsemi` 之 `rang` 以 `r += dx` 累加,`rang(-2, 2, 40)` 之 41 點中 39 點非整潔十進位值(中點為 `6.38e-16`);解值(`bestSolution.ps[].value`)即帶此誤差,入庫之門檻靠 `wround(…, 3)` 整潔.預設路徑因此**原樣保留**(含浮點),不改寫為整潔之陣列,否則解值與 2.0.42 不逐位相同.
- **自訂格點以查表還原**:`x ∓ vdir` 之浮點運算回不到原值(例 `(1/3 + 10) - 10 !== 1/3`),而取捨小數位會抹掉細格點;以 `Map(可用值 → { sym, th })` 查回格點原值,解值必為可用值之一(各演算法以索引取 `values[j]`,局部搜尋亦取最近之可用值).
- **平移後之可分辨性**:相鄰格點於平移後可能合併(例 `[-3, -3 + 1.5e-15, 3]` 之 `<` 組於 vdir 15 時合併,`>` 組不合併),故兩組各自檢查嚴格遞增;平移為單調之運算,平移後嚴格遞增即原值嚴格遞增,原值之檢查因此多餘(變異存活即為此),已併入平移後之檢查.
- **級距設定入識別**:`tkid` 帶完整之下界(`@1,3,6`),雜湊輸入沿用 `${coin}:${interval}:${tkid}` ⇒ 未給時與既有逐位相同、給予時不同設定之檔名必不相同(同資料夾混用互不覆寫);檔名之級距段仍為數字,`readStrategies` 之樣式判讀不必改.
- **觀察可用值之編碼**:`opt.funEndLoop(particles)` 可取得各粒子之 `ps[].{ind, value}`,據以逐位驗「`values[ind]` = 期望之編碼」(PSO 之 `funEndLoop` 於末代不呼叫,給 `Nl` 使至少跑數代).
- **公開函數加參數時用設定物件,不用位置參數**:`calcLevelNumTrade(numTrade, levelNumTradeBounds)` 之第 2 位置參數使既有之 `[3, 30].map(calcLevelNumTrade)`(回呼之第 2 引數為索引)由可用變為拋錯;改為 `calcLevelNumTrade(numTrade, opt = {})` 並以 `get(opt, 'levelNumTradeBounds', null)` 取值,非物件(索引、陣列)取不到即視為未給.測試須含回呼寫法(`map`、`Array.from`)與 `{}`.
- **走不到之防呆分支以替身最佳化函數測**:「解值非可用值時拋 `invalid x`」在各演算法皆以索引取值之下走不到;以子行程之模組解析鉤子(`module.register`)把 `w-optimization/src/omlPSO.mjs` 換成 `data:` 模組之替身(只評估一次、送入指定之解值),並以「送入可用值者照常完成」為鑑別前提.
- **時間口徑之相容性**:口徑之識別把缺 `timeBasis` 等同 `'open'`、`'open'` 時不計 `intervalSec`(只給 `intervalSec` 不改績效數字);否則日後對既有庫傳入 `intervalSec` 即被當成不同口徑而整批覆寫.檢測取用回測套件之同一實作(`src/barTime.mjs` 之預設匯出 `parseBarTime`).
- **相依下限已定時,不在本套件處理舊版與驗他套件之回傳形狀**(自有套件閉環,專案原則 14):提案原有「缺檔、無預設匯出、回傳形狀不合」三種拒絕與其替身測試,改為靜態匯入 `parseBarTime` + **契約測試**——直接核對實際 `parseBarTime` 之回傳(鍵序、值與型別)與 `estimKeys` 寫入 `settings` 之值相同、`package.json` 之下限 ≥ 1.1.43;日後回測套件改動回傳或訊息前綴時測試轉紅.靜態匯入亦免新增 `dist/` 路徑之動態載入風險.
- **檢測所用之運算須與實際使用之運算同一**:`thsTp`／`thsSl` 之檢測用 `round(候選 / 100, 3) > 0`,與設計變數(`values = 候選 / 100`)及取用(`rStopLoss = round(xs[0], 3)`)同一式;分開寫兩套判準(例如只判 `候選 > 0`)會漏掉「取捨後為 0」之候選(0.04),至回測時才拋錯.邊界測試須並列「取捨後為正」與「取捨後為 0」之兩值,並於測試內斷言此前提.
- **口徑覆寫規則之使用前提要寫在文件**:「口徑不同即不比優劣而覆寫」在同一資料夾有兩種口徑之寫入者時,會每輪互相整批改寫(震盪);須寫明「同一資料夾單一口徑、上游先支援轉傳才可改用新口徑」.
- **比對 wsemi 拋出之訊息,寫「名稱＋規則」形,不寫帶值形**:wsemi 1.9.70 起範圍錯誤改為 `invalid <名稱>: must …` 且不帶輸入值(例 `randomIntsNdpRange(0, -1, n)` 拋 `invalid vstart: must be <= vend`,舊為 `vstart[0] > vend[-1]`);本套件僅 `unit-estimComps` 以正規式比對 wsemi 訊息(其餘斷言比對之訊息為本套件自有,或來自其他自有套件〔`w-data-tdprovide` 之 `timeEndData`／`timeStartData`、`w-trade-backtest` 之 `parseBarTime`〕).期望寫到足以分辨同一欄位之不同錯誤(`must be <= vend` 對 `must be an integer`),不放寬為只比 `invalid vstart`.
- **相依之修改版尚未發布時之測試**:另建一棵 `node_modules`(複製安裝好之相依樹,把該相依換成修改版之快照,記下各檔之 sha256),在兩棵樹各跑全套.
- **模組解析鉤子之替身只攔截裸名**:以 `module.register` 之解析鉤子把 `w-trade-backtest/src/buildBaseUnitNotional.mjs` 換成 `data:` 模組之替身(檢測同真實、回傳另一組值)時,替身須以**檔案網址**取用真實之檔,且鉤子只攔截**裸名**之 specifier(不以解析後之 `r.url` 比對):以 `r.url` 比對則替身對真實檔之取用亦被攔截,自我遞迴(`Maximum call stack size exceeded`).
- **覆寫前比對 `keys`**(WS-KN-02):`tid` 為 `keys` 縮寫而得,碰撞案之構造:`name` 為 `btc`、週期 `4hr` 時 `btc_4hr_ma_1day` 與 `ma_1day` 得同一 `tid`(再各加一個第二 key `btc_4hr_rsi` 與 `rsi` 驗多 key 逐一比對).舊檔無 `keys`(缺欄或非陣列)者不比對(同 `tkid`／`name`／`interval` 各欄之寬鬆處理,舊版所存之檔不因此被拒);比對須先於基礎單位與時間口徑之判斷,否則口徑不同時會覆寫他組 `keys` 之策略(測試〈比對先於口徑〉以變異 K5 鑑別).

## 變異作法

- 變異一律在 `src/` 與測試之副本上做(`./tmp/` 下),不就地改 repo;每項自乾淨副本起算(等於還原),`find` 字串須在檔內恰出現一次,否則該項標錯誤而不執行.
- 存活之變異先判斷是測試缺口或等價變異:Gitea #182 之 76 項首輪存活 4 項——「`<` 組之符號被改為 `>`」(提案之測試只驗 `sym` 為 `>` 或 `<`、不驗與可用值之對應)、「各 key 共用同一可用值陣列」(規則寫「各一份副本」而無測試)、「多 key 時只比對首個 key」(碰撞案只有單 key)皆為測試缺口,以替身最佳化函數依序評估全部可用值、多 key 之碰撞案補強後殺;「`timeBasis` 寫原值而非 `parseBarTime` 之回傳」為等價變異(該函數對 `timeBasis` 不轉換).
- 測試之暫存資料夾用 `test/_tmp/<案名>/`(已被 `.gitignore`),與既有 `unit-setup.mjs` 之 `buildFdTmp`(`./test/tmp-unit-*`)並存;新測試依測試規範用前者.
